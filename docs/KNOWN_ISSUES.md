# Known issues: DUELL 0.2.20 beta

- **Tested on one unit.** The firmware has been flashed to and run on **one** real FM-1, the author's (it works). Other units, cables and USB hubs are untested. Use a data cable straight into the computer, no hub.
- **The way back to the official firmware** (V15) has worked on the author's unit about three times: the installer's return button wrote V15 and the unit booted normally. Other units are untested. Single-bank layout, no known rollback beyond that. See [RECOVERY.md](RECOVERY.md).
- **The editor and restore are not tested with many units.** The web editor (patch library, backup and restore, piano roll, wavetable files) and the installer's backup and restore have been tested on the computer with a simulated unit and on the author's unit only; other units, other computers and other USB-MIDI setups are untested, and the piano roll has not been used on a real unit yet. The backup covers patches, multis, patterns, the user wavetables, settings and the current music, but restoring a backup on another unit has not been tried.
- **The 128-patch export and import are untested on hardware.** The editor moves a whole patch with PATCH_RAW (in pieces over USB-MIDI). The USB-MIDI timing of a 128-patch export or import, the flash timing of 128 writes and playing while importing have been tested on the computer only (simulated flash and unit), not measured on a real unit. Do not import a whole bank while you play.
- **Very rare missed audio blocks.** When you switch to a very heavy multi, a block of audio can be late once in a while; you may hear a short click. Normal loads of patches and multis do not do this.
- **A slot shows the factory sound of the installed firmware.** The 128 patch slots hold the factory sounds until you save over one (RESTORE brings one back). The factory sound a slot falls back to is the one at that place in the list of the firmware you run: when a new version adds or sorts in sounds, a slot you never saved can show another sound than before, while a sound you saved stays in its slot number. Saves may change before the alpha.
- **The patch store can always be written.** There are 128 patch slots and a slot can never be full: the biggest possible saved sound is 434 bytes and 128 of them fit (16 chunks of 8), so a save never fails half way and there is no message about room. K1 on PATCHES steps one slot a turn (faster with KNOB ACCEL ON), so use TYPE (knob 2: FAV, a category or an engine) to shorten the list. The editor's patch page lists the 128 slots with a search.
- **Dual core is off and untested.** An optional second-core mode is planned, off by default; it has not been run on a unit.
- **MIDI is untested with many devices.** It follows the spec and the host tests; real controllers, sequencers and DAWs are still to be tested. The emulator takes notes and controllers from a WebMIDI device (not clock, not SysEx).
- **WAVE user tables are new and tested on the computer only.** The three slots (USR1 to USR3) are checked by host tests (flash places, CRC, power cuts, refusal while playing, backup round trip) and the editor's WAVETABLES tab against a simulated unit; the writes have not been tried on other units than the author's, and the editor tab has not been used to write a table on a real unit in a long session. A user table is reduced to 19 frames x 64 harmonics with no phases; a file with a very sharp or noisy sound loses its top and its character. An empty slot plays a sine. ERASE DATA erases the tables.
- **User sample slots:** gone since 0.2.9, with the sample engines. Slot 3's flash now holds the patch store; the WAVE user tables (0.2.14) sit in 24 KiB at the start of the old slot 1 range (0xA0000 to 0xA5FFF); the rest of the old sample flash (0xA6000 to 0xB9FFF) now holds the patch store's chunks 6 to 15 (80 KiB); 0xBA000 to 0xC7FFF (56 KiB) is free.
- **No rename on the device** for a stored patch or multi for now (the page buttons leave the NAME screen without writing); the editor can rename.
- **Saves may change before the alpha.** Until the alpha release, the way patches, multis, settings and everything else are saved may change. Saves may stop loading between versions, and a backup made with one version may not restore in the next. Do not rely on them yet.
- **Saves from older versions are not read.** Patches, multis and projects saved with 0.2.13 or earlier are not read by 0.2.20 (nothing is converted), and multis and projects saved by any build before 0.2.19 are not read either; the slots show empty (M01 to M10 show their factory versions). Old Felucca PROJECT data reads as empty. Patches saved by this build may read as damaged on older firmware. **Back up first.**
- **Emulator: your data lives in the browser** (this site's storage, on this computer only). After an emulator update, clear the site data if saved data from an older build misbehaves. Press "Download saved data" first. That file is emulator-only: there is no tool to move it onto a device.
- **Not built yet:** random-pattern action, tempo-synced ducker release.
- **Version text:** the device shows "DUELL 0.2.20 beta" (splash, ABOUT). The release has no TEST screen and no test multis.
