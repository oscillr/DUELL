**DUELL**
MultiMorphing Bitimbral Synthesizer
by OSCILL/R

Each release: a one-line summary, then New, Fixed, Compatibility, Install, Files.

## DUELL 0.2.20 beta

Four additions to the firmware (BASS MONO, a pitch and drift for the SHIM reverb, the patch store's PATCH_RAW command, and a mixer level apart from the sound's trim) and three to the web editor (a patch library with DX7 import and wavetable files, and a piano roll).

### Added
- **BASS MONO (a page of the GLO button, KNOB 1).** A sound setting, so it is not in the MENU. The page, after SIDECHAIN, is the master-stage page: it is called BASS MONO for now and will be MASTER when more master controls come to it. It is global, one setting for the instrument, and it is saved with each multi and with the project. Makes the output mono below a frequency you choose and keeps it stereo above it, so wide effects (SPACE, chorus, SPREAD, PING-PONG, the reverbs) do not smear the low end. It helps in clubs and when cutting vinyl.
  - **Values:** OFF (the default), then 40, 50, 63, 80, 100, 125, 160, 200, 250, 315 or 400 Hz. 100 to 150 Hz is the usual club setting. A multi saved with 100 Hz brings it back when it is loaded; the factory multis are OFF. In DUEL mode the card is not shown and the stage does not run.
  - **How it works:** the left-minus-right part of the sound is high-passed at that frequency (12 dB an octave, 3 dB down at the printed frequency); the middle is not touched. At 100 Hz a 40 Hz out-of-phase tone is 16 dB down; at 160 Hz, 24 dB down; a 2 kHz out-of-phase tone passes unchanged.
  - **Where in the signal path:** after the effects, SPACE and PERFORM, before MASTER and the limiter. USB audio gets it too (it is the same output).
  - **STEREO and LAYER only.** In DUEL (part 1 left, part 2 right for an external mixer) it would mix the two parts, so it does not run there and its card is not shown. The value is kept for when you go back to STEREO or LAYER.
  - **OFF is exactly the sound as before** (bit for bit). Switching it on or off, or changing the frequency, fades over about 25 ms: no click.
  - **Editor:** SETTINGS > AUDIO has the same setting (id 33). The editor cannot see the mode, so it keeps showing it, with a note that the unit ignores it in DUEL.
  - **Cost:** about 39 host instructions per sample while it is on (about 0.7 % of the device CPU, by the usual 1.7 % per 100 rule), nothing measurable when it is off. The fast RAM block is unchanged.
  - **Stored:** in the settings record (byte 29 of the last settings row, the old STYLE byte). Not in patches, multis or projects. A new unit, ERASE DATA and older settings records read OFF. ERASE DATA resets it.
- **The SHIM reverb can shimmer down, or both ways, and can drift.** With the reverb TYPE set to SHIM, a second page called **SHIMMER** follows REVERB:
  - **PITCH** (K1): **UP** (the shimmer an octave up, as it always was), **DOWN** (an octave down: a warm bed under the sound) or **BOTH**. BOTH is a little quieter on each side and about 8 cents sharp, which keeps the two from ringing on for ever at the longest SIZE.
  - **MOD** (K2): 0 to 100 %, **0 by default** (off). A slow drift of the shimmered part's pitch, so it does not stand still: about 10 cents at 50 %, up to about 25 cents at 100 %. Gentle at 40, wide at 100.
  - The SHIMMER page is **shown only with TYPE SHIM**: with ROOM, SPRING, HALL, RESO or PLATE the FX button and SELECT skip it, so there is no empty page. It is the last page of the FX family, so no page number moves. If the TYPE is changed while SHIMMER is open (from the editor, a multi or MIDI) the screen goes back to REVERB. With MODULES SENDS OFF its cards are not shown, like REVERB's.
  - **Nothing sounds different until you turn them.** UP with MOD 0 is the 0.2.18 SHIM bit for bit, so every factory multi (M02 WHISPER TIDE and the others that use SHIM) is unchanged. The values are saved in multis and projects.
  - **Editor:** a SHIMMER card under REVERB on the GLOBAL tab, shown only for TYPE SHIM.
  - **Cost:** the default costs nothing measurable; MOD or DOWN adds about 0.9 % of the CPU while SHIM runs, BOTH about 1.5 %.
- **PATCH_RAW (editor command 84, INFO tag `5A 01`): a slot's stored record, read and written whole.** UP_PUT drops End B, the arp / keys / SEQUENCER block and an FM6 sound's own patch; PATCH_RAW moves the record itself, bit for bit, in 112-byte pieces with a CRC-32 (INFO, READ, BEGIN, DATA, COMMIT, ABORT). It follows the rules of the other staged writes: refused while the sequencer plays (the unit stops it and answers rc 3 if it does not stop; nothing is written), power-cut-safe (the standard commit-last chunk write: the old record or the new one, whole), and the unit checks at the commit that the store would read the record (length, flags, today's form, an engine that exists, a printable name, every value in range). Every slot can always be written, also with all 128 holding the biggest record. The slot and revision bytes of a record are the unit's. EDITOR_PROTOCOL.md "PATCH_RAW (84)".
- **Editor, PATCHES tab: a library.** A compact list that fits the GLOBAL column (the checkbox, the number, the name, the engine, the type; saved patches in bold) and a **wide view** (all 128 slots on the full width, 16 to a row, for dragging between slots). **Export** one patch, a selection or the whole bank to a `duell-patches` file (JSON: the lossless record in base64 with a CRC-32, and a readable list of what differs from the engine's defaults, for diffing; a factory sound is a copy of its values and says so). **Import** from a patch file or a DX7 file dropped anywhere on the tab (or a button): a preview with name, engine and type, the target slots (the same numbers as in the file, or one after the other from a slot you pick, skipping saved patches if you like, or typed per patch), a list of what each write replaces, a safety copy downloaded first when four or more slots are written and a saved patch would be lost, a progress bar, and a read-back check of every patch. **Drag** a slot onto another to copy it (Shift: swap); in the wide view a drag swaps (Alt: copy); Copy to... and Move to... do the same without the mouse; the arrow keys move through the list. A patch, a patch file or a DX7 file **dropped on a part's column loads into that part live and is not saved** (the parameters the way the unit loads a slot, an FM6 sound with its own patch). docs/EDITOR_LIBRARIAN.md.
- **DX7 import.** A DX7 `.syx` file (a single voice of 155 bytes, a bank of 32 voices of 4104 bytes) shows its voices by name; the ones you pick become **FM6 patches that carry the voice** (the FM6 engine's own patch format, slot OWN). The owner's neutral defaults for our sections: a 12 dB low-pass MULTI FILTER at 6.8 kHz with a trace of resonance, REV 7 %, SAT / CHO / DLY 0, EQ flat, POLY (a bass voice MONO), the house LEVEL, no arp or keys. The name is the voice's, cleaned (capitals, 12 characters at most, never "DX7"); "DX7 sysex import" is only the label of where it came from; the type is a guess from the name. The parser is the older editor's, with wip/dx7fix's rule that only a damaged voice of a bank is left out (a bank with one damaged voice gives its other 31). The import was developed against public CC0 DX7 banks that are not shipped; the tests use synthetic banks generated in the test code, and you can try your own banks. Tested against the firmware: all 63 records of the synthetic test banks are taken by the store, load into a part with every parameter and the voice's patch, and render **bit for bit** what the FM6 engine renders when it loads the same voice with the same parameters.
- **Wavetables in the same library.** A WAV or a wavetable file can be dropped on a USR slot (anywhere on the WAVETABLES tab: the first empty slot); **Export file** saves a table from the unit as a small `duell-wavetable` file (JSON: name, 19 x 64, base64, CRC-32; about 1.7 KB) that can be dropped on another unit. A damaged or empty file is refused with the reason.
- **A piano roll in the web editor** (see [docs/EDITOR_ROLL.md](docs/EDITOR_ROLL.md)). Each part column has a **PIANO ROLL** tab, and its **ROLL** button opens the roll across the whole window with PART 1, PART 2 or BOTH. Steps run left to right (LEN of them, a line every 4 and a stronger one every 16), pitch runs up and down (C1..C7 and wider when the pattern needs it) with a keyboard on the left. Click to add a note, drag to move, drag the right edge for the length, right-click or double-click to delete; up to 4 notes in a step; a lane for velocity, chance and ratchet and a row each for accent and slide; LEN, DIV, SWG and GATE above the grid; copy, paste (also from one part to the other), clear; undo and redo (Ctrl+Z); arrow keys, Delete and Enter work without a mouse.
  - **It follows the unit's step model:** a note's length is its step and the TIE steps after it (as on the unit's own ROLL page), so the notes of a chord share one length, and velocity, accent, slide, chance and ratchet belong to the step. The roll cannot show a note that starts between steps (NUDGE is kept, not edited), parameter locks or automation, and it has no playhead (the protocol has no command for the position).
  - **Send live** writes each finished edit to the unit at once (STEP set, only the steps that changed); off, the edits wait for Send. A step edited on the unit's panel shows up in the roll.
  - **Hide rule:** with ARP MODE SEQ the steps are offsets for the held keys, so the roll shows one note per step and hides the length, slide, velocity, chance, ratchet, DIV, SWG and GATE; MODULES SEQ OFF (and ARP OFF with MODE SEQ) is said in a line, editing still works.
  - The editor cannot read the unit's SCALE and ROOT, so the roll's scale highlight is chosen in the roll and only colours the rows.
- **Tests:** `tests/bassmono_test.c` (bassmono), `tests/shimmer_test.c` (shimmer), `tests/level_test.c` (level), `tests/patchraw_test.c` (patchraw), `tests/dx7_import_test.c` (dx7import, with synthetic DX7 banks generated by `web/test_dx7_synth.mjs`; no real banks are in the repository; `DX7_BANKS=<folder>` adds your own, and `tests/dx7_compat.sh` (dx7compat) is the optional local engine / reference comparison that skips cleanly without banks), `web/test_librarian.mjs`, `web/test_roll.mjs` (both in editorjson), `web/test_librarian_ui.mjs` (headless Chrome, run by hand) and `web/test_rollbrowser.mjs` (rollbrowser; headless Chrome, skips itself when Chrome is not installed). The simulated unit now answers STEP_GET and STEP_SET and refuses what the unit refuses (more than 4 notes, a chance above 100, a ratchet outside 1..4, a nudge byte above 15, a byte above 127).

### Changed
- **A part's level is now two things, as on a real synth.** Before, one LEVEL did both jobs: it was the loudness of the sound and your fader. Loading a sound set it to the sound's value, so it undid what you had set on the mixer. Now:
  - **TRIM** is the sound's own loudness. It is saved with the patch (SAVE stores it, RESTORE brings the factory value back) and a multi keeps it with the sound. The factory sounds' tuned levels are trims, the same numbers as before, so the sounds still balance against each other. You find it on **EDIT > VOICE 2/2, knob 4** (GLMOD, GLD, SPRD, TRIM). It is shown in dB, default -4.0.
  - **LEVEL** is the volume you set on the mixer (**MIXER knob 4**, the GLO page knobs 3 and 4, the editor's LVL, MIDI **CC7**, MIDI LEARN). It is not part of a patch: loading a sound, changing the engine, INIT, UNDO or a MIDI program change never touches it, so a part 2 you turned down stays down. A multi and the project remember it. Default is unity, 0.0 dB (before, a fresh part was at -4.0 dB; the sound's trim makes up the same loudness, so a new part sounds as it did).
  - The part plays at the trim and the level together (the two dB values add). The total is held at +7.5 dB at most. With the level at unity every sound is exactly as loud as before: the regression renders and the 14 factory multis (at three MORPH positions each) come out bit for bit the same.
  - The mod matrix destination that was called LEVEL is called **TRIM** and moves the sound's trim, not your mixer level.
  - **PAN** is no longer on EDIT > VOICE 2/2. It is a mixer setting that a sound load leaves alone, like LEVEL, so it stays on the MIXER (knob 2) and in the editor's part header. VOICE 2/2 has the TRIM in its place.
- **Editor:** the part header's LVL is the mixer level; the TRIM is a card on the ENGINE tab (VOICE 2/2). A patch saved from the editor holds the trim and no mixer level. The library reads and writes patch records in the same form (the trim, no mixer level); a patch dropped on a part keeps that part's mixer level.
- The editor's simulated unit knows PATCH_RAW, UP_GET, UP_PUT and the FM6 patch (FM6_GET / FM6_PUT, target 0), keeps whole records and loads a slot the way the unit does: a saved sound brings its own TRIM and keeps the part's mixer LEVEL, PAN, MUTE and arp ids. It reports the current version (0.2.20 bet).
- The `?mock=old` simulated unit has no PATCH_RAW (firmware 0.2.13): the library buttons are not drawn there and a line says why.
- **Editor and Backup page connect by themselves** when the browser has already been allowed MIDI with SysEx for the page: at load, and when the unit is plugged in later (not after you press Disconnect). The first time a browser needs one click on Connect to allow it (a browser rule); until then the page says so. Nothing in the protocol changed.

### Fixed
- **Display:** a level of exactly 0 dB reads 0.0 dB (it read .0 dB); the same for values like 0.5 dB.
- **#23 KICK BASS and #96 HARD KICK sit at kick pitch.** They sounded too high on the normal keys (F3 gave 175 Hz for HARD KICK). #96 HARD KICK now plays two octaves lower and #23 KICK BASS one octave lower (its sub was already an octave below the key): the lowest body is 44 Hz on F3 and 65 Hz on C4 for both. A sound cannot store the part's TRN, so each carries a constant matrix route to PITCH (EXPR, -64 each: -12 semitones per route); a CC11 below full lifts the pitch back up. Louder to match (TRIM 107 and 113); #23 has a new End B seed.

### Removed
- **OUTPUT EQ (the low cut and BASS+).** The MENU > AUDIO row OUTPUT EQ (FLAT, LOWCUT, BASS+) is gone, with the filters and the speaker bass behind it. With FLAT, the default, the sound is exactly what it was (the test renders hash the same). MENU > AUDIO now has USB LEVEL, CLICK, CLICK LEVEL, COUNT-IN and TUNE. Editor setting id 9 is retired. A saved setting of it is ignored.

### Compatibility
- **Multis and projects saved by 0.2.18 or earlier are not read** (multi version 5, project revision 3). The slot shows empty; M01 to M10 show their factory versions, which keep their loudness. Autosave from the older build is ignored at power-on.
- **Patches you saved before are kept and read.** The loudness an old patch held (its LEVEL) is now its trim, so it plays as loud as before, and it no longer sets your mixer level. The next save over it writes the new form.
- Parameter ids, the number of parameters and the file sizes did not change: the trim uses the id of the old DUCK HOLD, which nothing read. The patch store's biggest record is 434 bytes (was 435). Records written now carry a new flag (bit 2, PTF_TR); a unit before 0.2.19 does not read them.
- The editor protocol has a new parameter, TRIM (id 109), a new command, PATCH_RAW (84, INFO tag `5A 01`), and a new setting, BASS MONO (id 33, shown by the editor as a BASS MONO card of the GLOBAL tab); the SHIM's PITCH and MOD use ids 26 and 17, which were stored as 0. All are in EDITOR_PROTOCOL.md. A unit before 0.2.19 does not answer command 84: the editor still lists, loads, saves and restores, but cannot take or give a patch whole (it hides the file buttons).
- Nothing else is refused: the new SHIM values and BASS MONO read 0 in older multis and projects, and 0 is the old sound (BASS MONO is in two spare bytes: byte 5 of a multi and byte 65 of a project). A multi saved with 0.2.19 is not read by 0.2.18 (multi version 5).
- **Untested on hardware.** The library and the piano roll are tested on the host (simulated flash, simulated unit, headless Chrome); the USB-MIDI timing of a 128-patch export or import, the real flash timing of 128 writes and playing-while-importing are not measured.

### Size
- the app is 433,988 bytes (0.2.18: 429,076; the limit is 581,564); RAM .data+.bss 51,104 of 73,728; the pool spare is 29,172 bytes (0.2.18: 29,200); the fast RAM block is 12,348 bytes, 164 free (0.2.18: 12,312, 200 free); taking out OUTPUT EQ freed about 640 bytes of flash, 112 of RAM and 16 of the fast block; the start-up layout check (elfcheck) passes. The package is 610,086 bytes.

## DUELL 0.2.18 beta

### Changed
- **A control that does not apply is not shown (owner rule, 2026-10-15; it replaces the faded card with its reason).** When a choice makes a control useless, its card is **not drawn**: its column stays empty, the other cards keep their knobs (K1 to K4 stay where they were), and the knob of the empty column does nothing and says nothing. There is no reason text on the card and no `MODULES: ... OFF` line in the footer any more. It is one rule for the whole unit and the web editor:
  - **The delay:** in DIGITAL the SPREAD card is not shown; PING-PONG hides nothing; in RANDOM and OCT UP the MRATE card is not shown (MDEPTH is CHANCE there); in DUEL the MODE and SPREAD cards are not shown.
  - **MODULES:** a module that is OFF hides the cards it makes useless (ARP: the arp pages; SEQ: the arp cards of a SEQUENCER arp, AUTOMATION's PLAY; SENDS: CHORUS, DELAY, REVERB, the FX page's sends, SPACE on the MIXER and PERFORM; PART FX: SAT, INSERT, EQ, DUCK, SC SRC and SC NOTE). The value is kept and acts again when the module is ON.
  - **Other cards:** INSERT A, B, C and MIX while the INSERT is OFF; the ADSR of FM6; a synced LFO's RATE; the PAN card in DUEL (MIXER and VOICE); TEMPO and TAP with an external MIDI clock; SC NOTE with a PUMP or PART source; XFADE and SPLIT outside LAYER; P1 CH and P2 CH while MIDI IN is SELECTED (P2 CH in LAYER); OFF-SCL while the scale is CHROMATIC; FAV on a sound in no slot; RESTORE on a slot with no saved sound (PATCHES) and RESTORE ALL when none is saved (SAVE > TOOLS).
  - **Not hidden:** the cards that are the choice itself stay (the MATRIX DEST card, shown dim when the route does nothing now, and CHRD on DIA3 / DIA7 with no scale); a value of zero is never a reason. A page whose cards are all hidden (INSERT 2/2 with the INSERT OFF) stays in the page cycle with its title and four empty columns, so page numbers never move.
  - **Editor:** the same controls are hidden (their place stays empty); no reason text. Buttons are sized by their text, so MONO and AUTO are no longer cut off at 1920 x 1080 and 1280 x 720; the DELAY MODE is a list; the stale "MODULES switches do not exist" note is gone.
- **Page order, top-down (owner rule: a mode or type first, an amount next, a level or mix last; from the page-order audit).** Only the order of the cards moved; no stored value, patch, multi, project, matrix route or MIDI LEARN assignment changed (they go by the parameter, not by the knob).
  - **MIXER:** MUTE, PAN, SPACE, LEVEL (was LEVEL, PAN, SPACE, MUTE). **MULTI FILTER:** CUT, RES, MODE, SLOPE (unchanged); QUICK MULTI (hold EDIT) is CUT, RES, MODE, REL (unchanged). **ARP:** 1/3 MODE, HOLD, ORD, OCT; 2/3 RATE, GATE, SWG, PROB; 3/3 TRGT (QUICK ARP is as before). **TEMPO:** CLK, TEMPO, TAP, SWG (the source first: with an external clock the TEMPO and TAP cards are not shown). **DUCK 2/2:** CURVE, ATK, RLS. **VOICE:** 1/2 VCE, PRIO, ALLOC, DTUNE; 2/2 GLMOD, GLD, SPRD, PAN.
  - **FM6:** the SLOT card is now first, on EDIT 1: SLOT, ALG, FB, MLVL; EDIT 2 is MRAT, MEG, VMOD, DTUN (the pages are called PATCH and MACRO). Only the cards moved: SLOT is still stored where it was.
  - **Left as they are:** TRIO's PW (it would move a stored slot), AMP DEST's ESYNC, INSERT 2/2 and ARP 3/3 (one card each, forced by the number of cards), SPACE on the MIXER (a global macro on a part page, on purpose: it is PERFORM's K2 too).
  - **Editor:** the tabs follow the same order.
- **The delay's modulation controls say what they are: MRATE and MDEPTH.** On DELAY 2/2 the cards RATE and DEPTH are now **MRATE** (modulation rate) and **MDEPTH** (modulation depth), so they are not mistaken for the chorus's or an LFO's. In RANDOM and OCT UP the depth card is still CHANCE. The matrix destinations DELAY MOD RATE and DELAY MOD DEPTH keep their full names; their short names stay DMRAT and DMDEP (MRAT is FM6's own label). The stored values and ids are unchanged.

- **Size:** the app is 429,076 bytes (0.2.17: 429,504; the limit is 581,564); the pool spare is unchanged at 29,200 bytes; the fast RAM block is unchanged (12,312 bytes, 200 free).

### Compatibility
- **Multis and projects saved by 0.2.17 or earlier 0.2.x are not read** (the delay MODE: multi version 4, project revision 2, first made in the delay-mode work that is in this build). The slot shows empty; the factory multis M01 to M10 show their factory versions (with the same sound, bit for bit). Saved patches, patterns, settings and wavetables are unchanged and read as before. Back up with the editor before you update if you need a multi.
- Parameter ids, patches and the editor protocol are unchanged by the hide rule, the page order and the MRATE / MDEPTH names; the FM6 cards moved but SLOT is still stored where it was.

  - **LEAD:** #27 SQUARE LEAD (ANALOG, a mono square with portamento), #42 SCREAMER (WAVE, the YELL table).
  - **PAD:** #50 PLATE CHOIR (VOICE, a choir that leans on a big reverb; it shines on the PLATE reverb type).
  - **PLUCK:** #65 ARP PLUCK (ANALOG, a synth pluck that plays itself as an up arp).
  - **KEYS:** #84 TUBE BELLS (FM6, a tubular bell with the Chowning 5:7 ratio).
  - **PERC:** #96 HARD KICK (PHASE, a hardstyle kick: a sine with a pitch drop, hard-clipped).
  - **FX:** #110 TAPE DRONE (WHEEL, a slow organ chord on the TAPE insert).
  - The hard basses and HARD KICK have no PUMP ducker; every bass keeps the high-shelf cut; ARP BASS and FM BASS 2 keep the subtle PUMP. Basses are dry.
- **FM6: three more factory patches, F9 to F11, behind the voice bank.** MENU > the SLOT card goes on after B32 with F9 (FM BASS 2's voice), F10 (TUBE BELLS) and F11 (FRETLESS). They sit after the bank so the stored SLOT values of F1 to F8, OWN and B1 to B32 mean what they meant: saves, projects and user patches are not affected (a stored value above OWN has always loaded as OWN, with the patch coming along). F9 is a voice of the CC0 collection credited below, adapted (the name, the carriers' sustain so that a held key holds), and played through DUELL's own multimode filter (12 dB, a gentle low-pass), a SOFT insert and the bass shelf.
- **Credits:** One FM voice: aquanodemusic (Aquanode Soundscapes), CC0 1.0 Universal, https://github.com/aquanodemusic/aquanode-soundscapes. In NOTICE.md, LICENSING.md and MENU > ABOUT > CREDITS (FM VOICE).

### Changed
- **One list of 128 patch slots, filled by the factory (owner decision, 2026-10-15).** There is no longer a "user patch" and a "factory patch": **slot #NN is the factory sound at position NN of the PATCHES list** (category, engine, name: the numbers of docs/PATCH_NUMBERS.md) until you save a sound there. A new or erased unit shows the factory sounds in all 128 slots (nothing is written for that), and a slot can never be empty, full or "free".
  - **SAVE writes into a slot and overwrites what is there.** Hold SAVE on any page: one dialog, "OVERWRITE #12 <name>?", for the slot your sound came from (a sound that came from no slot gets the slot of its factory sound). **Turn knob 1 in the dialog to pick another slot**; the line under the question says what is written ("WITH <name>") and OCT+ writes. With TARGET BOTH on the MORPH page it asks "OVERWRITE BOTH PATCHES?" and writes each part over its own slot (two parts from the same slot: "SAME SLOT", nothing written). The sound keeps its name; the NAME screen and "SAVE AS NEW SOUND?" are gone (the device has no rename; the web editor renames).
  - **RESTORE brings the factory sound back.** The old ERASE card on the PATCHES page is **RESTORE** (knob 4, a turn right asks "RESTORE #12 TO <factory name>?"). It removes the saved sound from the slot; the part that played it plays the factory sound. It is only active when the slot holds a saved sound: on a factory slot the card is faded with the reason FACTORY and a turn says ALREADY FACTORY.
  - **RESTORE ALL is on SAVE > TOOLS** (K3, the third action after CLEAR and INIT; OCT+ asks "RESTORE ALL PATCHES?"). It removes every saved sound, chunk by chunk, each chunk a power-cut-safe write; a cut leaves some slots restored and the others as they were, never a damaged one, and doing it again finishes. The card is faded FACTORY when nothing is saved.
  - **No counts and no "user" words.** The PATCHES cards show the slot's number (#42) instead of "42 /145"; the ERASE card's "17 /128", "FREE nn", "NO FREE PLACE (ERASE ONE)", the empty places at the end of the list, "EMPTY PLACE" and "U007" are gone from the device and from the editor ("N of 128 patches used"). The list is the 128 slots in slot order; a row is "#12 FOLD BASS". TYPE (all, FAV, a category, an engine) filters the same list by what the slots hold now. The EDIT layer's sound list (its "No." card) lists the slots that hold a sound of the engine. K1 acceleration (KNOB ACCEL ON) is as in 0.2.16.
  - **Favourites are the slot's.** A star stays on the slot through a save and a restore (before: factory sounds by engine and index, saved patches by slot). Stars you set in 0.2.16 on factory sounds are not read any more (saves may change before the alpha).
  - **MIDI program change n loads slot n** in bank 0 and bank 1 alike (before: bank 0 was the list in its old order, bank 1 the stored patches). Bank select is read as before; other banks and programs past 127 are ignored.
  - **A saved sound loads at its own LEVEL** (as a factory sound does: the part's PAN and MUTE stay). Before, a saved patch left the part's LEVEL alone, and only a saved copy of a factory sound brought its trim.
  - **A slot you never saved shows the factory sound of the firmware you run.** When a version adds or sorts in sounds, a slot you never saved can show another sound than before; a sound you saved stays in its slot number. This is the price of "nothing is written until you save". Saves may change before the alpha: no compatibility is promised.
  - **Stored format:** the records are unchanged; the shadow marker of 0.2.15 / 0.2.16 (a record that named the factory sound it copied) is not written any more and is ignored when read, so a copy made by those betas is simply the saved sound of its slot number. The patch store's RAM directory lost two bytes an entry (20 instead of 22), 2,560 bytes in all. **Size:** the app is 429,504 bytes (430,132 before this change; the limit is 581,564), RAM .data + .bss 51,120 bytes (51,136), the pool's spare 29,200 bytes (28,944), the fast RAM block unchanged (12,312 bytes, 200 free); elfcheck passes. Backup and restore carry the saved records only, as before; a restore puts them back into their slots.
  - **Editor protocol** (the commands and frames are kept inside this firmware generation, EDITOR_PROTOCOL.md "v2: the patch slots"): UP_LIST and UP_GET report every slot as holding a sound and add a SAVED byte (1 a saved record, 0 its factory sound); UP_STORE and UP_PUT overwrite a slot; **UP_ERASE of a slot is RESTORE** (rc 0 and no write when it holds its factory sound); the capacity tag 58 01 still says 128. No command lists free places any more. **The editor's PATCHES tab is the grid of the 128 slots:** search and an engine filter, load a slot into a part, save a part's sound over a slot (an overwrite confirmation), rename, Restore (enabled only for a saved slot) and Restore all. The grid is the base for the later librarian (drag and drop of banks, import), which is not built yet.
  - **Tests:** a fresh unit shows the factory sounds in all 128 slots (names, engines, categories and values equal a factory load); SAVE then reload equals the saved sound; RESTORE brings the factory sound back bit for bit; RESTORE ALL; program change; favourites; a power cut at every step of a SAVE, a RESTORE and a RESTORE ALL (about 190, 230 and 110 cut points: every slot its old content or the new one, the others untouched); the PATCHES page and its dialogs through the layout lint (no cut text); the editor against the simulated unit, whose slot numbering is checked against docs/PATCH_NUMBERS.md.
- **The PATCHES numbers moved.** The number is the sound's place in the list (category, engine, name), so the 14 new sounds renumbered 113 of the old 114 (BEEHIVE stays #1). Nothing else follows the number: saves, favourites, the factory multis, End B seeds and the MIDI program changes (stored patches) keep their identity (a MIDI program change is a slot number, 0.2.17 above). The list of old and new numbers is in docs/PATCH_NUMBERS.md; SOUND_RECIPES.md and SPEC.md quote the new ones. Older entries of this file keep the numbers they had when written.
- **FRETLESS and SLAP DOCTOR no longer sound alike.** Both used the ROUND BASS patch with near-equal settings (and SLAP DOCTOR's ENV 2 slap was routed nowhere). FRETLESS now has its own FM patch F11: a warm, near-sine bass whose tone opens after the pluck (the "mwah") with a legato glide. SLAP DOCTOR is the bright, clicky slap: ENV 2 really opens the modulators at the strike and they fall within about 0.3 s. A new test (fmbass) keeps them apart (the energy above 250 Hz at 200 ms differs by 33 dB, the transient by 5 dB). Their End B seed (FRETLESS) and LEVEL were redone.

## DUELL 0.2.16 beta

### Added
- **WAVE user tables: three slots of your own, USR1 to USR3 (TABLE 26 to 28).** After the 26 factory tables the TABLE knob has three more places. A user table is made on the computer from a WAV file and sent to the unit by the editor; the unit keeps it (flash, with a CRC) and plays it like any table.
  - **What a user table is:** 19 frames of 64 harmonics, one byte each (a level in 0.38 dB steps, the frame's strongest harmonic is the top). Every harmonic is a sine, the same in all frames, as the factory tables are, so POS mixes two frames as a mix of their spectra. **Phases are not kept, and a file with more frames or more harmonics is reduced to 19 and 64: the editor says so.** A Serum-style file (256 frames of 2048 samples) keeps 19 evenly spaced frames and loses the harmonics above 64 (for a sharp saw that is about 0.9 % of the energy, 20 dB down, the bright edge) and the phases.
  - **Name:** up to 8 characters, set when you send it; TABLE shows it (a card shows the first five). A slot with no table is named **EMPTY** and plays a plain **sine** in every frame. A patch, multi or save names a user table by its number only; the table stays in the slot. On a unit where that slot is empty, or holds another table, the patch plays the sine, or the other table.
  - **Writing is only ever done by the editor, never while the sequencer plays.** The unit stops the sequencer first and refuses (rc 3) if it does not stop; the flash write ducks the audio like any save. A part that is playing the slot fades out and builds the new table (a moment of silence, like a TABLE change). A power cut during a write leaves the old table.
  - **Where they live:** flash 0xA0000 to 0xA5FFF (USR1 0xA0000 and 0xA1000, USR2 0xA2000 and 0xA3000, USR3 0xA4000 and 0xA5000: an A/B pair of 4 KiB sectors each, 1228 bytes of table). This is the first 24 KiB of the old user sample region; the patch store takes the next 80 KiB (0xA6000 to 0xB9FFF, see Changed) and 0xBA000 to 0xC7FFF (56 KiB) stays free. A firmware update never touches it. ERASE DATA erases the three tables too (they are your data).
  - **Backup:** the editor's backup holds the three tables (object ids 24 to 26, INFO backup caps bit 3); a backup file with them is "version 3".
  - **Editor protocol:** WT_LIST, WT_GET and WT_PUT (commands 81 to 83), see EDITOR_PROTOCOL.
  - **The converter** (`web/editor/wavetable.js`, with a try-out page `web/editor/wavetable_demo.html` that talks to the editor's simulated unit): reads PCM and float WAV files, frames of 256 to 4096 samples (or any size of 130 and up: a 600 sample cycle works), a whole file of 2048-sample frames (the clm chunk of Serum, Vital and Surge names the size), picks 19 frames evenly, takes the first 64 harmonics with an FFT, scales each frame, and shows the spectrum and what is lost. The editor page for it is not built yet.
  - Credits: the FFT (Cooley and Tukey, 1965) and the 2048-sample wavetable file convention (Xfer Serum, also Vital and Surge) are credited in NOTICE.md, LICENSING.md and MENU > ABOUT > CREDITS. No code of other projects is used.
- **CLK AUTO: the clock finds itself, and it is the new default.** GLO > TEMPO, KNOB 4 CLK now offers AUTO, INT, USB, TRS. On AUTO, DUELL plays on its own tempo until a MIDI clock arrives on USB or on the TRS MIDI input; then it follows that clock. When the clock stops for about a second, DUELL goes back to its own tempo.
  - **Nothing stops when it switches.** The pattern, the arp, the synced LFOs, envelopes, delay and PUMP keep running. When the clock goes away, DUELL carries on at the last tempo and in time, with no gap.
  - It takes three clock ticks to switch (a single stray tick is ignored), or a Start / Continue from that input, which switches at once.
  - While it follows one input, the other input's clock and Start / Stop are ignored.
  - Start, Stop and Continue from the followed input work as with CLK USB or TRS.
  - The CLK card shows AUTO with the clock in use under it (INT, USB or TRS). The TEMPO card shows EXT with USB or TRS under it while it follows a clock. Each switch says CLOCK USB, CLOCK TRS or CLOCK INT in the header.
  - INT, USB and TRS work as before.
- **GLO > MODULES: switch the arp, the sequencer, the send effects and the part effects off for the whole unit.** A new page after MIDI (GLO, TEMPO, SIDECHAIN, MIDI, MODULES, MIDI LEARN) with four switches, each ON (the default) or OFF: K1 ARP, K2 SEQ, K3 SENDS, K4 PART FX. Turn a knob right for ON, left for OFF.
  - **ARP OFF:** no arp plays, whatever its MODE says; the keys play directly (chord keys still work). HOLD ALL still latches the keys; HOLD ARP latches nothing while the arp is off. REC (as HOLD) switches between OFF and ALL.
  - **SEQ OFF:** the step sequencer plays no stored steps: PLAY and a MIDI Start run the tempo, the arps and the synced LFOs, but no step, lock or automation. The arp's SEQUENCER mode is off too (it plays the same steps). You can still edit and record steps, and STEP PREVIEW still sounds them.
  - **SENDS OFF:** the chorus, delay and reverb (and SPACE) are switched off after a short fade, and their processing stops: this saves a lot of CPU (about 9 to 21 % on the factory multis). Switched on again, they start clean, with no old echo.
  - **PART FX OFF:** each part's SAT, INSERT, EQ and DUCK are bypassed after a short fade (up to about 11 % CPU saved when they are used).
  - These are device settings: kept when you power off, not saved in patches or multis, and a multi load never changes them. A new unit, ERASE DATA and the update start with all four ON. Nothing you set on the ARP, SEQ or FX pages is changed: switch a module ON and it plays as before.
  - While a module is OFF, the cards it affects are greyed with a short reason (ARP OFF, SEQ OFF, SND OFF, FX OFF) and the footer says it in full, for example MODULES: SENDS OFF. You can still turn them; the value is kept for later. PERFORM's effects are never switched off.
  - OCT- held + a knob switches that module back ON. The web editor shows them in a MODULES group.
- **PLATE, a sixth reverb.** REVERB > TYPE now has ROOM, SPRING, HALL, SHIM, RESO and PLATE: a smooth, dense plate reverb in stereo, with a slow gentle movement in the tail. SIZE is how long the tail lasts (about 0.5 s at 0, 3 s at 90, 6 s at 127), DAMP how dark it gets as it fades. It works in STEREO, LAYER and DUEL (each part's own reverb on its own side), with the SENDS switch and with SPACE, and you can change to it and away from it while a tail rings without a click. It uses no extra memory and about 1.3 times the CPU of ROOM (a little more than HALL). Based on the reverb of the CHOMPI firmware (MIT), which is Emilie Gillet's plate reverb from Mutable Instruments Rings and Clouds (MIT); the licence notices are in LICENSES/MIT-CHOMPI.txt and NOTICE.md.
- **Two new delay modes: RANDOM and OCT UP bend the repeats on the beat.** The delay now has a MODE, the first card of DELAY 1/2: DIGITAL (the delay as it always was), PING-PONG (the repeats alternate left and right, as the old PING switch did), RANDOM and OCT UP. The cards read DIGI, PING, RAND and OCT+; the header says the full name when you turn MODE.
  - **RANDOM:** on a random share of the clock edges the repeat is retriggered a little late, played backwards, an octave up or an octave down, for one beat; then the plain delay comes back. **OCT UP:** the same chances, but always an octave up, with a random place in the stereo image; fed back, the octave-up repeats climb, and COLR (the delay's tone) tames them.
  - The clock is the delay's own TIME: one edge per delay time (1/8 note: an edge every 1/8 note), counted from PLAY and following the tempo and an external clock like the delay does. On DELAY 2/2, DEPTH becomes **CHANCE** (0 to 100 %: the share of the edges that fire an event; it is the same stored value as DEPTH, so a DEPTH of 40 is a CHANCE of 40). The matrix destination for DEPTH reads CHNC in these two modes. RATE (the delay's slow modulation) does not exist in them and fades with the mode's name as the reason. SPREAD is the width of the repeats, FDBK, COLR and MIX are the delay's as before.
  - **CHANCE starts at 40 %.** Turning MODE into RANDOM or OCT UP while the stored DEPTH / CHANCE is 0 sets it to 40 % and the header says CHANCE 40 %, so the mode does something at once (the CHOMPI original starts its randomness knob at 0, so there is no number to copy; its events fire on at most half of the edges, DUELL's 100 % is every edge). Turning MODE back to DIGITAL or PING-PONG puts that 40 back to 0 if you did not touch the knob meanwhile, so the delay sounds as it did; a DEPTH that was not 0 is left as it is, and a multi that stores RANDOM with CHANCE 0 keeps its 0. The web editor does the same when you change MODE.
  - **Stereo:** RANDOM and OCT UP are not a second ping-pong: the repeats do not alternate left and right. The left channel reads the delay line, the right one 10 ms behind it (a small width), the events sit in the middle (RANDOM) or at a random pan of up to 60 % to either side (OCT UP), and SPREAD sets the width. The alternating left/right echo is the mode PING-PONG.
  - PING-PONG, RANDOM and OCT UP are STEREO and LAYER only: in DUEL (each part its own delay) the plain delay runs and the MODE card fades with DUEL. The delay time of these modes is at most 0.74 s (a longer TIME halves, as it did for PING-PONG).
  - Changing the mode while the delay rings crossfades in about 12 ms: no click. SENDS OFF and STOP ALL clear it like the rest of the delay. It uses no extra memory for the sound (it reads the delay's own line), 76 bytes of state, and costs about 45 more host instructions per sample than the plain delay between events (about 1 % CPU) and about 130 to 165 when events sound most of the time (CHANCE 50 to 100: about 2 to 3 %), 100 to 130 more than PING-PONG. About 3.3 KB of flash. No lock yet.
  - Based on the idea of the granular delay in the TEMPO firmware of CHOMPI (CHOMPI Club, MIT); written again here in integer code, no code copied.
- **REVERB LOW CUT: no reverb makes the bass muddy.** The REVERB page has a fourth card, K4 LOCUT: a gentle high-pass (6 dB an octave) on what goes into the reverb, in front of every model: ROOM, SPRING, HALL, SHIM, RESO and PLATE alike. It shows its corner in Hz, from 20 Hz to 450 Hz on an even-step scale (each step about 2.5 % higher), and OFF at 0. It starts at 88 Hz (value 61), a mild cut: low notes keep their body in the dry sound, but they no longer fill the reverb with boom. Only the reverb's input is filtered; the dry sound, the chorus and the delay are not. It is one setting for the whole unit, kept in saves and multis like SIZE and DAMP; in DUEL each part's reverb has its own filter. It works with SPACE (SPACE does not bypass it), with MODULES SENDS and with PERFORM. Turning it is smooth, no click or zipper noise. It also removes any steady offset from what the reverb gets, which PLATE needed. At OFF the reverb sounds exactly as before. It costs about 0.16 % CPU a bus.

### Changed
- **The DELAY pages are in logic order, top-down: MODE first, MIX last, and PING-PONG is a mode.** DELAY 1/2 is MODE, TIME, FDBK, COLR (the kind of delay, then its loop); DELAY 2/2 is SPREAD, RATE, DEPTH, MIX (the stereo width, the slow modulation, the level at the end of the chain). Before, MIX was on the first page and DELAY 2/2 began with a PING on/off switch; the extra DELAY MODE page is gone, so the delay has two pages. The modes: **DIGITAL** (clean repeats with a low-passed feedback, COLR, and the optional modulation: the old delay with PING off), **PING-PONG** (the old PING on), **RANDOM**, **OCT UP**. A new unit starts in DIGITAL, which sounds exactly as the old default (PING off); DIGITAL and PING-PONG sound bit for bit as the old delay with PING off and on.
  - **Cards that do not apply:** SPREAD does nothing in DIGITAL (the plain delay has no side), RATE does nothing in RANDOM and OCT UP, and in DUEL the MODE and SPREAD cards do nothing (the ping-pong and the new modes are STEREO and LAYER only, as before). Since 0.2.18 these cards are not shown at all (see 0.2.18).
  - **Saved settings:** a multi and a project written by 0.2.16 store the mode as 0 DIGITAL, 1 PING-PONG, 2 RANDOM, 3 OCT UP. The format markers moved (multi version 4, project revision 2), so multis and projects saved by earlier 0.2.x firmware are not read: the slot shows empty (the factory multis M01 to M10 show their factory versions, now with the new mode), as for the earlier format changes before the alpha. Back up with the editor before you update if you need anything from them.
- **PATCHES, KNOB 1 with KNOB ACCEL ON: a fast turn goes faster through the list.** The list is the 128 patch slots and KNOB 1 used to move one place a click whatever the speed. With MENU > KNOB ACCEL ON (the default) a quick turn now moves 2 to 8 places a click, as the other wide knobs do; the first clicks of a turn, a slow turn and a turn the other way stay one place. A fast turn stops at the first or last place (it does not run round); a single slow click at the end still goes round. **Only the sound the turn ends on loads:** while the turn goes on the cursor moves and no sound is loaded, and the sound under the cursor loads 150 ms after the last click, so the audio does not glitch on the sounds passed. With KNOB ACCEL OFF nothing changed: one place a click, each loaded at once. (The PRESETS knob is as before: one place a turn.)
- **The patch store holds 128 patch slots, and every one of them can always be saved, whatever the other 127 hold.** Before it held 48. The biggest possible saved sound (an FM6 sound with its patch, a SEQ-mode arp with 16 steps, End B and every value off its default) is 435 bytes; 8 of them fit a chunk, and the store now has 16 chunks, so 16 x 8 = 128 of them fit: a save never fails half way, and no message about size or room exists (a slot is never "full"). Typical sounds are 55 to 90 bytes (an FM6 sound about 170 to 190), so the 16 chunks are mostly empty room. The 128 slots are one list: a slot holds the sound you saved there, or else the factory sound at that place of the list (0.2.17 above).
  - **Where:** ten new chunks (ten more A/B pairs of 4 KiB sectors, 80 KiB) at 0xA6000 to 0xB9FFF, next to the six old ones. A payload ends at sector offset 0xF00 as before (the updater scans the last 256 bytes of a sector; a compile-time check and a test make sure). **0xBA000 to 0xC7FFF (56 KiB, 14 sectors) stays free** for later. The old store is read as it is, nothing is wiped. A firmware update keeps it; ERASE DATA erases all sixteen chunks.
  - **RAM: 14.8 KB of the pool back.** The patch store no longer keeps a copy of its chunks in RAM (23 KB). It keeps a small list (128 entries: where each saved sound is, its name, engine and category) and reads a saved sound from flash when it is loaded or edited. Pool spare 14,140 to 28,944 bytes; the app is 427,948 bytes (was 427,444); the fast RAM block is unchanged (12,312 bytes, 200 free). (0.2.17: see its numbers above.)
  - **The PATCHES page:** the list is the 128 slots; the cards show the slot's number and no count of used or free places.
  - **Program change:** program n is slot n, 0..127.
  - **Editor:** the patch page is the grid of the 128 slots; it shows no "N of 128 used" and reads the slot count from the unit (INFO tag 58 01).
- **The firmware is 29 KB smaller and uses 1.4 KB less RAM.** The app is 421,408 bytes (it was 450,020; the limit is 581,564), so 160,156 bytes are free for new features. Nothing you can use changed; see Removed.
- **PERFORM lets go of SPACE and KILL when you leave it.** Before, leaving PERFORM reset KILL only, and SPACE stayed where you left it, even after you loaded another patch ("still in immense space"). Now, by default, when you leave PERFORM, load a patch or load a multi, SPACE and KILL glide back to neutral in under half a second (0.4 s from the ends of the knob, no click, no jump): SPACE to the patch's own sends, KILL to OFF, and then the sound is exactly the patch's own again. A SPACE you set on the MIXER page alone is left alone when you only open and leave PERFORM. DEPTH and MORPH stay as they are.
  - **MENU > CONTROL > PERF LEAVE: FADE (default) / KEEP.** KEEP leaves SPACE and KILL as they are after you leave PERFORM and after any load, and the cards keep showing the live values.
- **In PERFORM the black keys play in the scale.** They still play notes, now moved to the nearest note of the SCALE and ROOT you set, even if OFF-SCALE says PLAY (CHROMATIC: unchanged). Outside PERFORM nothing changes.
- **The multimode filter's page is called MULTI FILTER, and the DIST knob is called SAT.** On ANALOG the engine's own filter page is VCF and the multimode one was just FILTER; now EDIT > MULTI FILTER (its hold layer: QUICK MULTI) is clearly not the engine's own filter. TRIO FILTER and NOISE FILT stay as they are. The FX page's first knob, the part's DIST, is not much of a distortion (it is gentle), so it is now SAT (saturation): the card, the matrix destination (DEST SAT, SATURATION on its line), the MORPH and editor labels and the PART FX text on MODULES. Nothing stored changes: sounds, matrix routes and the editor's ids are the same. PERFORM's K3 FILTER (the DJ filter) keeps its name.
- **PERFORM's K3 FILTER is now KILL, and the matrix destinations say MULTI FILTER.** K3 is the DJ-style filter that goes to silence at both ends (the kill zone), so it is named for what it does and no longer shares the name FILTER with the EDIT pages; its reset says RESET KILL. In the matrix, the destinations FILTER CUTOFF and FILTER RESONANCE are now MULTI FILTER CUTOFF and MULTI FILTER RESONANCE on the DEST line (the stored numbers are the same).
- **The MENU is tidier.** Hold HOME for it. Its rows, tab by tab:
  - **DISPLAY:** COLOR, LEDS, SCALE LEDS (moved here from CONTROL), ANIMATION, SCREEN OFF, CPU METER.
  - **CONTROL:** MULTI LOAD, HOME OPENS, KNOB ACCEL, BUTTON HOLD, STEP KEYS, STEP PREVIEW, PERF LEAVE.
  - **AUDIO:** OUTPUT EQ, USB LEVEL, CLICK, CLICK LEVEL, COUNT-IN, TUNE.
  - **SYSTEM:** RESTORE LAST, BUTTON MAP, USB SERIAL, GUIDE, ABOUT, ERASE DATA.
- **New names, same jobs.** ANIM is now ANIMATION. HOLD is BUTTON HOLD (how long you hold a button for its quick layer). SPEAKER EQ is OUTPUT EQ (it acts on every output, not only the speaker). MODE RECALL is MULTI LOAD: KEEPS MODE (the default) or SETS MODE (a multi load also sets MODE, BALANCE, XFADE and SPLIT). CHORD ENTRY is STEP KEYS: WRITE or ADD. CALIBRATION is BUTTON MAP (it teaches the firmware which button and knob is which; you never need it in normal use).
- **USB SERIAL shows a second line, DEVELOPER CONSOLE**, so you know what it is.
- **A tab with more rows than fit on the screen gets a second page**, shown as SYSTEM 1/2 in its tab. SELECT goes through every row and every page as before.
- **New defaults:** KNOB ACCEL is ON (fast turns move big values faster), CLICK is REC (the metronome clicks while you record on the sequencer pages), USB SERIAL is OFF.
  - A new unit and ERASE DATA start with them.
  - **After the update, once:** KNOB ACCEL is set ON, CLICK OFF becomes REC and USB SERIAL ON becomes OFF, because the firmware cannot tell whether you chose the old value or never touched it. If you had set them that way on purpose, set them again in the MENU: from then on your choice stays.
  - With USB SERIAL ON, macOS 13 to 15 do not show the USB audio input; OFF fixes that. Turn it ON only if you use the serial console.
- **QUICK MULTI (hold EDIT) is the multimode filter on every engine.** K1 CUT, K2 RES, K3 MODE of the multimode filter (the MULTI FILTER page's), K4 the amp envelope's REL, the same on all ten engines. On ANALOG, TRIO and NOISE it used to show the engine's own filter instead (ANALOG: CUT, RES, TYPE, so K3 switched the VCF between LP and BP). Their own filters are still on their EDIT pages: VCF, TRIO FILTER, NOISE FILT. SLOPE stays on the MULTI FILTER page.
- **The MIXER page shows both parts side by side.** Part 1 on the left, part 2 on the right, like the GLO page: each side has the part's number and sound, LEVEL in dB, PAN (in DUEL fixed: LEFT / RIGHT, greyed), the REV, DLY and CHO sends and a MUTE mark when muted, with the two level meters of the GLO page (peak hold, CLIP) between them. The knobs still edit the selected part (LEVEL, PAN, SPACE, MUTE); its side has the bright outline in its colour, and ALGORITHM switches the part. Before, the two parts were two strips one above the other.
- **CRUSH BITS works over the whole knob.** Before, 16 to 9 bits took half of the knob and sounded alike, so the first clicks from 16 changed nothing. Now every detent is a different depth, and the number on the card follows it (the nearest whole bit count):
  - 1 bit at the left end, 10 bits at about 85 % of the knob, then 11 to 16 bits in the last 18 detents, 16 (clean) only on the last two.
  - Between the whole bit counts the depth is in-between, so there are no dead clicks. The card shows the whole number; 16 is shown only where the sound is really clean.
  - **Your saved sounds keep their sound.** Patches, multis, saved work and the factory multis load with CRUSH on the same bit count they had (checked bit for bit). The factory sound GLASS SHARDS is still 8 bits. A new CRUSH on a part with the knob untouched starts at about 6 bits (the knob stays where it was; the old default was 9 bits). The default for a reset of the BITS knob (OCT- and the knob) is 9 bits.
- **USB name: the unit shows up as DUELL, made by OSCILL/R.** It was FELUCCA by Hügelton Instruments. Same USB vendor and product numbers (0x1209 / 0x0001). The installer and the web editor find it by either name. The update loader keeps its own name.
- **The hottest audio code runs from the chip's RAM** instead of the flash (the filter, FM6 operators, WAVE, the effects chain). The sound is the same; only where the code runs changes. Every build is checked after linking (tools/elfcheck.py).
- **Two new INSERT types, TAPE and VINYL, at the end of the TYPE list.** They share the INSERT's MIX (0 is the part untouched, bit for bit) and the same fade when you change TYPE or MIX. Each part has its own.
  - **TAPE:** WOW (how far the pitch drifts, slowly and at random, 0.5 to 2 Hz; 0 holds it still), SAT (a soft saturation, 1x to 5x, the level kept about the same), TONE (a gentle high cut). A flutter of 6 to 9 Hz (about 3 cents) and a faint hiss are always part of TAPE.
  - **VINYL:** DUST (the crackle, clicks of random size and sign a second: 0 none, about 1 at the left end, about 16 in the middle, about 250 at the right end), NOISE (a quiet bed of high-passed noise; 0 none), WARP (a light wobble of the pitch once a turn of a 33 rpm record, 0.56 Hz; 0 holds it still). The sound is always narrowed a little (below about 110 Hz and above about 6 kHz); the crackle and the noise are added after that.
  - The hiss, the dust and the crackle are there while the part sounds (and for a moment after); the INSERT does not run on a silent part. The same part and the same settings always give the same noise.
  - Each costs about as much as PHASR (about 2.8 % of the device's half per part with a 4-note part, measured on the host model; not yet on a unit).

### Fixed
- **Installer: the backup works with this firmware.** The installer's "Save a backup file" refused DUELL 0.2.14 and later ("This firmware cannot make a complete backup"): it expected the 16 song rows the old Felucca sent, and DUELL sends none, and it did not know the longer list of objects (30 with the user wavetables, 40 with the 16 patch chunks of 0.2.15, whose ids 35 to 39 it also took for sample slots). It now reads the unit's INFO tags, takes the list the unit sends (16, 27, 30 or 40 objects) and saves them all: patches (all 16 chunks), multis, pattern slots, wavetables, settings and the music. The file is the same "felucca-backup" file as before; the editor's Backup page restores it, and a file from an older unit still restores onto a new one (the chunks it lacks are emptied) and a new file onto an older unit (what that unit does not know is skipped). The note under the button now tells the truth about what is in the file.
- **STOP ALL now silences the effect tails too.** Pressing PLAY/STOP twice (or holding it) used to stop the voices but let the delay, chorus and reverb ring on, for more than 30 s with SPACE at +100. Now their lines fade out in about 25 ms, are cleared, and the sends fade back in about 22 ms later, so the next notes sound as normal. It works in LAYER, DUEL, STEREO and SPLIT with every reverb type. A double press on a stopped unit does it too. A single STOP is unchanged (the tails run on), and GLO > MODULES SENDS OFF stays OFF.
- **ELASTIC BASS (#8): its MORPH End B now does something.** End B was too close to the sound; its amount is 11 % and it was rolled again: B is rounder and deeper (more at 100 to 200 Hz, a little less top), still the same acid bass.
- The keys and buttons no longer flash bright for a moment when DUELL saves; they go dark for that moment instead.
- USB: the audio input is listed before MIDI so macOS 15 and older show it; computers may treat the unit as a new device once.
- **PERFORM K3 KILL (was FILTER): no more noise or crackle.** Turned from the middle it added noise, and deep into the low-pass it crackled (the old filter ran out of precision at low cutoffs). It is now a new 24 dB/oct stereo filter: low-pass to the left, high-pass to the right, still exactly off in the middle and silent at -100 / +100. Clean at every setting, a smooth sweep while you turn, a steeper slope.
- **SAT: the first detents no longer jump.** SAT 1 used to cut the bass and the level at once, so the step from OFF was audible. Now SAT 1 to 11 mixes the clean sound with the saturated one (1/12 of the effect at 1, 11/12 at 11); from 12 up it is the same sound as before. SAT 0 is still the plain, untouched sound. Switching SAT on from 0 also starts its filters fresh, so it no longer carries leftovers from the last time it was on.
  - Factory sounds with a small SAT, or with a small SAT in their End B, now sound a little cleaner at the low end. ELASTIC BASS and WALL OF SAW got a smaller MORPH AMOUNT (6 % and 15 %, was 7 % and 17 %) so their End B stays as loud as the other sounds'.
- **FM6: amplitude modulation sensitivity (AMS) was broken.** Any 6-operator voice with AMS above 0 on a sounding operator was scrambled (noise, mutes, or up to four times full level), even with the LFO's AMD at 0, which is how many DX7 banks are set. AMS now follows the DX7: AMD 0 changes nothing, and AMD raises the dip with AMS 1 to 3. No factory sound uses AMS, so none of them changes. Found by running 384 voices from 12 public DX7 banks through the engine: 7 voices clipped and 19 were noise-like before, none clip and 3 are noise-like now (those 3 are noisy in the voice data too).
- **Editor: one corrupt voice no longer drops the rest of a DX7 bank.** A voice with bytes above 0x7F (not valid MIDI data) used to end the import there and lose every voice after it. Now only that voice is skipped, and the editor names it ("corrupt voice skipped: #31 Klick"); the others are kept.

### Added
- **A small CPU meter in the header.** Under the battery, on every page that has the header, a 5 px bar shows how busy the sound engine is, measured over the last second. It takes no room from the page name or the octave display, and nothing changes in the sound. MENU > DISPLAY > CPU METER turns it ON (the default, also for saved settings) or OFF. CUT is the cutoff, shown in Hz, from 30 Hz up to 16 kHz. MODE blends smoothly from low-pass (LP) through band-pass (BP) to high-pass (HP); in between the card shows LP>BP or BP>HP. SLOPE is 12 dB or 24 dB per octave (24 dB is steeper and uses a little more CPU, only while the filter is working). A fully closed filter is silent: over the last 4 steps at the closed end the sound fades out completely (for the low-pass at 30 Hz, for the high-pass at 16 kHz). With MODE on LP and CUT fully open, which is the default, the filter is switched off and the sound is exactly as without it. The envelope, LFO and matrix routes to the cutoff, and the matrix's FRES, work as before. Turning MODE or SLOPE while a sound plays does not click.

### Changed
- **Scale lights: the root is steady and the other scale keys are brighter.** The root keys no longer pulse; they are lit steadily at about 75 % of full. The other keys of the scale are lit at about 40 % of full (before: 25 %), in every LEDS mode. The root is clearly brighter than the other scale keys, and a key you hold or that is sounding is still lit fully. Keys outside the scale are unchanged.
- **HOLD has a third value, ALL: the keys latch with the arp off, for pads and drones.** HOLD (ARP 1/3) now reads OFF, ARP or ALL. ARP is the old ON and works as before; ALL keeps a played chord sounding after the keys are released, with the arp off too (keys and MIDI), the next chord replaces it, and OFF or STOP ALL ends it. Each part holds its own chord. Older patches, multis and projects load unchanged.

Saved patches, multis, projects and the last session are converted when they load and sound the same: a low-pass at exactly the same cutoff, a high-pass as MODE HP at practically the same cutoff, OFF as the filter fully open. Their recorded CUT automation is converted too. The five factory sounds of 0.2.8 that use the filter (EVOLVING PAD, REESE BASS, HOOVER, DIGITAL PAD, BREATH PAD) sound exactly as before; only their MORPH End B moves the cutoff a little differently (the CUT knob has 82 steps now, and a random End B that used to cross the old middle into a high-pass now stays a low-pass).

- **PERFORM's FILTER closes completely.** K3 FILTER's low-pass now goes all the way down to 30 Hz (it stopped at 120 Hz) and the high-pass up to 15 kHz (it stopped at 3.8 kHz), and over the last 4 steps at each end the sound fades to silence. In the middle it is still exactly OFF.
- **The web editor** shows the new FILTER page under EDIT (CUT in Hz, MODE as LP / BP / HP) and converts an older library sound before it plays it on the device.
- **SPACE no longer changes the delay time; it changes the delay level and feedback.** Turning PERFORM's SPACE used to stretch or shorten the delay time slowly, which bent the pitch of the echoes while it moved and sounded weird. Now the echoes stay in time and in tune. SPACE still makes the chorus, delay and reverb smaller to the left and bigger to the right: their levels, the reverb's length, the delay's feedback and the chorus depth. At the far right the chorus depth now goes only up to the DEPTH knob's own maximum (it was twice that, an audible pitch wobble). In the middle everything sounds exactly as before.
- **SPACE now also adds reverb, delay and chorus when the sends are at 0.** Turning SPACE to the right used to only multiply each part's sends, so a sound with its sends at 0 got no space at all. Now, turning right, every part sends at least a minimum amount to the reverb, delay and chorus, which grows the further right you turn (at the far right at least as much as a reverb send of 76, a delay send of 46 and a chorus send of 30; less into the SHIM and RESO reverbs, which would otherwise clip). A part whose own send is already higher keeps its own, raised by SPACE as before. In DUEL each part only goes into its own effects. Turning SPACE to the left still only shrinks what is there.
- **SPACE also sets the stereo width.** Turned to the left it narrows the sound down to completely mono at the far left; turned to the right it widens it (without making it louder). A sound that is mono stays mono. In DUEL the left and right outputs are the two parts, so the width is left out there (the rest of SPACE works) and the header says DUEL: NO WIDTH the first time you turn SPACE.
- **The row of sequence dots at the bottom now shows only on the sequencer pages** (STEP, AUTOMATION and SEQ TOOLS). On the other pages that row is empty, except where it already showed something else (MIDI LEARN, PERFORM, the PATTERNS and MULTIS save hint).
- **ABOUT: KNOB 1 scrolls, SELECT jumps between sections.** On MENU > SYSTEM > ABOUT, turn KNOB 1 right to scroll down through the information, credits and licences and left to scroll back up. SELECT now jumps to the next or previous section (the animation, the information, CREDITS, LICENSES), and OCT- goes back to the menu. Before, SELECT scrolled and turning a knob left left the page.
- **Factory multi M03 DEAD BUFFER:** part 1 played #2 STRETCH on the removed GRAIN engine; it now plays FROZEN AIR (WAVE), a slowly scanned airy texture with the same envelopes, movement and effects. Everything else of M03 is as it was: part 2 (MODEM), your own changes to part 1 (the auto-pan, the drive), the effects, the mode, the tempo and End B. If you saved over M03 yourself, your saved version is kept and its part 1 is silent until you choose a sound for it.
- **ERASE DATA's dialog** now says the FM6 voice bank is kept (it said user samples).

### Fixed
- **SPACE turned to the right no longer glitches.** While SPACE moved, the chorus jumped a little on every audio block, a fast crackle on any sound with chorus (the same happened when the chorus DEPTH was turned or moved by the matrix); the SPRING reverb did the same while its size changed. ### Fixed
- Load-time CPU spikes: loading a patch or a multi, or changing the mode or the reverb, no longer misses audio blocks in normal use (very heavy multis can still click, see KNOWN_ISSUES). PHASE is much cheaper (PHASE + ANALOG measured on the unit: 63 % average, 71 % peak, 0 missed).
- LFO routes to PAN, DIST, sends and engine macros did nothing audible with an arp; an arp is now one LFO phrase.
- The arp now follows an external clock (USB / TRS) that runs without a Start; a Stop makes it wait again. The TEMPO and MIDI pages show NO CLK when the external clock sends nothing for 1 s.
- SPLIT checked for leakage over every send, reverb, insert, EQ, ducker and DIST (the other channel is digital silence); stereo-only controls that SPLIT does not use are shown faded with the reason SPLIT.
- A restored autosave never brings back a muted part.

## DUELL 0.1 beta (emulator release; firmware to follow)

**First public beta: Felucca turned into a two-part, morphing synth for the FM-1. The browser emulator is published first. The firmware has been run on one real FM-1 by the author; the firmware package follows after more hardware testing (including the return to the official firmware, which is untested).**

### New (compared to Felucca)
- Two parts, with SPLIT, STEREO and LAYER modes (BALANCE, velocity XFADE, key SPLIT).
- MORPH between End A and End B, with smart random (ROLL A or B, UNDO, one AMOUNT), saved with the patch.
- PATCHES (one list, factory and yours; up to 48 stored patches, FREE nn on the card), 16 MULTIs, 16 named PATTERNs.
- ENV 2 and LFO 2, 8-slot modulation matrix.
- Effects: per-part EQ, per-part ducker with MIDI/pulse/part sidechain, ping-pong delay, SHIM and RESO reverbs (from JIANT).
- MIDI: a channel per part, clock in, program change and bank select, a CC map, mod wheel to morph.
- All MIDI settings on GLO's pages (MIDI with P1 CH, P2 CH, MIDI IN OWN CH / SELECTED and the clock source CLK; SIDECHAIN; MIDI LEARN with CLEAR), none in MENU. GLO's pages in order: GLO, MIDI, SIDECHAIN, MIDI LEARN, TEMPO (K1 TEMPO, K2 SWG, K3 TAP: a detent either way is one tap), TEST.
- GLO's main page no longer takes over the keys: they play notes. K1 MUTE and K2 SOLO turn left for part 1 and right for part 2 (one action per twist, the MORPH page's gesture), K3 LEVEL 1, K4 LEVEL 2, with a dB meter per part between the columns. MENU re-audited: OVERVIEW (SCOPE / PARTS) and HOME OPENS (MORPH, MODE, MIXER, OVERVIEW), INFO and ABOUT also open with KNOB 1. A new unit starts in VIOLET, LAYER, with factory multi M01 loaded.
- A sound palette sorted by category, nine colour themes, a navigation scheme where SELECT selects and knobs adjust.
- A CPU load meter (MENU > SYSTEM > INFO: 1 s average, peak hold, missed blocks), a power-on splash (DUELL title block over the morphing wave lines, any key skips), an ABOUT page with the title block, version and Felucca credit. VIOLET is the default theme.
- GLO > TEST, the CPU test page (the meter moved here from INFO; shows the multi, each part's engine and patch; K1 MORPH, K2 ROLL, K3 LOAD MULTI, K4 RESET) and four factory TEST multis M13..M16 (TEST 1 BASE, TEST 2 PHASE, TEST 3 HEAVY, TEST 4 MIX) for measuring the load on real hardware (docs/TESTING.md). ABOUT now opens on the splash animation (SELECT scrolls to the information).
- Installer page and docs (this release). The installer says "firmware not yet released" and its flow is disabled until the package `duell-0.1-beta.fwsc` is published; the device shows "DUELL 0.1 beta".

### Fixed
- Nothing to report: this is the first release.
